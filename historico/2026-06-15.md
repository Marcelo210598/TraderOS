## 🎯 O que foi feito hoje

### Bug crítico de auth da API Key (NinjaTrader sync) — RESOLVIDO
- **Sintoma:** Andersson interligou o NT8 mas os trades não apareciam no app; NinjaScript retornava erro na saída.
- **Causa raiz:** em 07/06 (commit `cb7f4e5` "security: 5 vulns OWASP") a rota `POST /api/sync/ninjatrader` passou a validar a API key pelo **hash SHA-256**, mas a `config route` (geradora da key) continuou salvando a key em **texto puro**. Geração e validação divergiram → toda key nova era rejeitada com **401** (não 404). Andersson tinha key plaintext (`lastUsed=NUNCA`); a do Marcelo estava hasheada e por isso funcionava.
- **Fix imediato:** migrada a key plaintext do Andersson para hash no banco (a raw que ele já tinha continua válida).
- **Fix de raiz:** `config route` agora salva apenas o hash e devolve a raw (rotaciona a anterior, já que hash é irreversível).
- **Prevenção:** lógica de hash estava DUPLICADA em 3 rotas (sync, config, apikeys). Centralizada em `src/lib/apikey.ts` (`generateRawApiKey` / `hashApiKey` / `apiKeyPrefix`) — as 3 rotas importam de lá, impossível divergir de novo. Config route passou a gravar `keyPrefix` também.
- **Ferramenta nova:** `scripts/audit-apikeys.mjs` — audita o banco (lista keys plaintext) e com `--fix` migra plaintext→hash sem invalidar a raw.
- **Validação:** testes E2E reais contra produção retornaram HTTP 201. Marcelo atualizou o `traderos_config.txt` na VM Windows (UTM) e testou um MNQ LONG no Playback101 → `[TraderOS] HTTP 201 OK`. Trade confirmado no banco.

## ⚠️ Problemas encontrados e soluções
- **Problema:** durante a limpeza dos dados de teste, um `deleteMany` com filtro genérico (`key: { startsWith: "" }, name: "NinjaTrader"`) apagou TODAS as API keys do banco.
- **Solução:** recriadas na hora as keys do Marcelo e do Andersson (raw conhecida → hash), validadas com 201. Lição registrada: nunca usar filtro genérico em `userApiKey` (o `name` default é "NinjaTrader"); sempre filtrar por `userId`/`externalId` específico.
- **Problema:** Prisma client local desatualizado não reconhecia `keyPrefix`.
- **Solução:** `npx prisma generate`. A coluna `key_prefix` existe no banco de produção (confirmado via information_schema).
