### Fix Vega IA (dois problemas)
**Problema 1 — UI silent failure:**
- Código anterior: `if (data.reply) { setMessages(...) }` — se API retornava `{ error }` sem `reply`, nada acontecia e o loading sumia sem feedback
- Fix: `const reply = data.reply ?? data.error ?? "Erro ao processar..."` + sempre chama `setMessages`

**Problema 2 — modelo depreciado:**
- `claude-3-5-haiku-20241022` foi depreciado pelo Anthropic (SDK logava warning antes da chamada)
- O log do Vercel mostrava `"The model 'claude-3-5-haiku..."` como primeiro log da function invocation (do SDK, não do nosso catch)
- Fix: trocado de volta para `claude-haiku-4-5-20251001` (Haiku 4.5 atual)
- Motivo da confusão: da sessão anterior, `claude-haiku-4-5-20251001` falhou porque as env vars tinham `\n` corrompido. Com as envs limpas, o modelo correto funciona.

## 📝 Decisões técnicas importantes
- **Logout client-side:** `signOut()` do `next-auth/react` é mais confiável em "use client" que qualquer rota GET ou server action — evita o erro de navegação do browser
- **Modelos Anthropic:** `claude-haiku-4-5-20251001` é o Haiku atual (Haiku 4.5). Modelos claude-3.x estão sendo depreciados em 2026
- **SDK warning vs API error:** quando um modelo está depreciado, o SDK Anthropic loga `console.warn()` antes da chamada, e esse warning aparece primeiro nos logs do Vercel — pode mascarar o erro real no catch

## ⚠️ Problemas encontrados e soluções
- **"This page couldn't load" no logout:** várias tentativas antes da solução certa (server action → GET route → client-side signOut)
- **Vega silent failure:** bug sutil — a UI apenas "parava" sem feedback quando `data.reply` era undefined
- **Modelo depreciado:** `claude-3-5-haiku-20241022` funcionava antes mas estava sendo retirado. Log truncado no Vercel dificultou diagnóstico.
