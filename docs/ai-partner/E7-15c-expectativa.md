# E7-15c — Cliente Groq + rota do chat: decisões e expectativa (21/10/2026)

Só documento. Nenhum código de produção, nenhuma chamada à Groq, nenhum deploy.

## 1. Fatos medidos (21/10/2026)
- **Groq `qwen/qwen3.8-27b`** (página oficial): tool calling local, tool use paralelo, JSON mode, "Preview"; `reasoning_effort="none"` = modo instruct (sem raciocínio); `reasoning_format="hidden"` esconde o raciocínio; formato OpenAI (`tools[].function`, `tool_calls[].function.arguments` = STRING JSON, mensagem `tool` com `tool_call_id`); `history`: em multi-turno só a saída final, sem raciocínio.
- **Limites de taxa do modelo na tabela base da Groq** (por ORGANIZAÇÃO, não por usuário): 30 req/min, 1.000 req/dia, **8.000 tokens/min**, **200.000 tokens/dia**. 429 ⇒ header `retry-after` (s). Cabeçalhos `x-ratelimit-*` sempre presentes. Os limites reais da conta do Marcelo estão em console.groq.com/settings/limits (só ele vê). **Risco de viabilidade:** um turno pode gastar até 16.000 tokens (teto do E7-15a) e usar 2–12 requisições; com 8K tokens/min e 200K/dia o chat só comporta alguns turnos por minuto/dia para TODOS os usuários juntos. Um plano pago da Groq (Developer, por uso) eleva os limites, mas tem custo e exige cartão: decisão do Marcelo.
- **Vercel**: projeto `trader-os`, região das Functions `iad1` (Virgínia), Fluid compute ligado, timeout padrão 300 s, Node 24; o time aparece como plano `hobby` (a conferir pelo Marcelo; o termo "Hobby" da Vercel é para uso não comercial). Banco Neon e R2 em `sa-east-1`/global: cada ida ao banco custa ~100+ ms a partir de `iad1`.
- **Dependências de produção** (`buildAiPartnerDeps`): hoje devolve só `rawStorage`, `importStore`, `salts`. O chat precisa de mais: `conversations` (`createPrismaConversationStore` + `createConversations`), `ChatQuotaStore` (`createPrismaChatQuotaStore`) e o cliente Groq (`GROQ_API_KEY`; `GROQ_MODEL` opcional). `GROQ_API_KEY` já está na Vercel (Production, sensível); NÃO está no `.env.local` (só para o E7-15d).
- **Rota de referência**: `handleImportPost` (pura, `ctx` injetado) + rota fina + `_ctx.ts`; plano lido do banco a cada pedido; rate limit `hit(...)` fail-open; Origin/CSRF; erros com mensagem FIXA e `Cache-Control: no-store`.
- `importStore.list(userId)` devolve as importações (com `createdAt`); o pin do turno é escolhido pelo SERVIDOR (`MAX_PIN_SOURCES = 10`).

## 2. Decisões
- **D-G1 Cliente Groq** (`infra/groq-client.ts`, implementa `ModelPort`): `fetch` e relógio INJETADOS; chave injetada (nunca em log, erro nem resposta). Pedido: `model` (do ambiente, padrão `qwen/qwen3.8-27b`), `messages` no formato OpenAI (`toolCalls` ⇒ `tool_calls` com `arguments` em string; mensagem `tool` com `tool_call_id`), `tools` no formato `{type:"function",function:{...}}`, `tool_choice` `auto`/`none`, `reasoning_effort:"none"`, `reasoning_format:"hidden"`, `max_tokens` por chamada (ponto de partida 1.500), sem outros campos. A resposta final NÃO usa `response_format` (tools + JSON mode juntos são incertos); o prompt já exige JSON puro.
- **D-G2 Saneamento da saída:** remove `<think>…</think>` e cercas de código; `arguments` string ⇒ objeto (JSON inválido ⇒ `null`, que o executor trata como `ARGS_INVALID`); `usage.total_tokens` ausente/estranho ⇒ `undefined` (o laço já conta como teto: fail-closed).
- **D-G3 Erros** (mapeados para `{kind:"error", code}`, sem texto do provedor): 429 ⇒ `RATE_LIMITED` (com `retry-after` interno), 5xx/rede ⇒ `UPSTREAM`, tempo esgotado/abort ⇒ `TIMEOUT`, 400/401/403/404 ⇒ `CONFIG` (log estruturado só com código+status). Sem retry automático (YAGNI): a cota é devolvida e o usuário tenta de novo.
- **D-G4 Tempo:** prazo do turno 50 s (`TURN_DEADLINE_MS`), por chamada no máximo 25 s ou o que restar; a rota declara `maxDuration = 60` (o lease de 90 s a cobre).
- **D-G5 Rota** `POST /api/ai-partner/chat` (`infra/ai-partner-chat.ts`, pura; rota fina + `_ctx`): sessão → configurado? → Origin/CSRF → limite por minuto do usuário (5/min) → corpo JSON ≤ 8 KiB com chaves estritas `{ question, conversationId?, fileSha256? }` → plano do banco → escolhe o pin (importação mais recente, ou `fileSha256` do PRÓPRIO usuário) → SEM importação ou sem sal ⇒ `409 NO_IMPORTS` ANTES de reservar cota e de chamar o modelo → guarda global de turnos/min (D-G7) → `withChatQuota(runChatTurn)` → 200 `{ ok, conversationId, outcome, response, usage:{used,limit,remaining} }`.
- **D-G6 Mapa de respostas:** `QUOTA_EXCEEDED` ⇒ 403 `{upgrade, limit, used, suggestedPlan}`; `TURN_IN_PROGRESS` ⇒ 409; `MODEL_ERROR` ⇒ 503 `MODEL_UNAVAILABLE` (a cota já foi devolvida); `NOT_FOUND` (conversa de outro usuário/inexistente) ⇒ 404; `TURN_CONFLICT`/`LIMIT_EXCEEDED` ⇒ 409 (`CONVERSATION_FULL` sugere conversa nova); `INVALID_ARGS` ⇒ 400; demais ⇒ 500 mensagem fixa. Nunca ecoa pergunta, exceção, SQL, URL ou chave.
- **D-G7 Guarda global da Groq:** os limites são da ORGANIZAÇÃO; conferido ANTES de reservar a cota (não consome): no máximo `GROQ_GLOBAL_TURNS_PER_MIN` turnos por minuto no total (constante, ponto de partida 4 enquanto o plano for o base); estouro ⇒ 429 `BUSY` com `Retry-After`. Fail-open no Upstash (se cair, a cota e o 429 da Groq seguem protegendo). Valor definitivo depende dos limites reais (decisão do Marcelo).
- **D-G8 Dependências:** novo montador `buildAiPartnerChatDeps(env, prisma)` (não altera o `buildAiPartnerDeps` do upload): sem `GROQ_API_KEY`, `R2_*` ou `SALT_MASTER_KEY` ⇒ `NOT_CONFIGURED` ⇒ 503.
- **D-G9 Sem deploy neste passo:** a rota existe no código, mas só vai à produção depois do E7-15d (medição com a Groq real) e da tela (E7-15e), com OK explícito.

## 5. Emenda (21/10/2026) — medições que mudam o desenho
- **Limites confirmados no print da conta (nível base, organização "Personal"):** `qwen/qwen3.8-27b` = 30 req/min, 1K req/dia, **8K tokens/min**, **200K tokens/dia**; a página diz que só o plano Developer sobe os limites.
- **Peso FIXO por chamada (medido em `chat-turn.ts`/`system-prompt.ts`, estimativa caracteres/3,5):** ferramentas 17.485 caracteres (≈ 5.000 tokens; `metrics_compare` sozinha 5.083) + prompt 3.012 caracteres (≈ 860) ⇒ **≈ 5.900 tokens por chamada**. Um turno de 2–3 chamadas passa de 13K tokens: estoura o teto de 8K/min e o de 16K por turno do E7-15a. Minha estimativa de custo por mensagem (R$0,024–0,053) estava BAIXA; o E7-15d mede o real.
- **D-G10 Ferramentas compactas:** as definições das 8 ferramentas passam a ser enxutas (sem `$schema`, `additionalProperties`, `default` nem descrições por campo além do essencial; mantém `type`, `enum`, `required`). Orçamento fixado em teste: JSON de TODAS ≤ 7.000 caracteres (≈ 2.000 tokens) e cada uma ≤ 1.500. A validação rigorosa continua no servidor (zod). Prompt do sistema ≤ 3.200 caracteres. A ordem das mensagens mantém o prefixo estável (sistema + ferramentas primeiro) para o cache de prompt da Groq (tokens em cache não contam nos limites, segundo a documentação; a medição real é do E7-15d).
- **D-G7 revista:** no nível base `GROQ_GLOBAL_TURNS_PER_MIN = 1` (cada turno ≥ ~5–8K tokens e o limite é 8K/min para TODOS). Com 200K tokens/dia o nível base serve ~25 turnos por dia no total: é só uma demonstração. **Não liberar o chat a usuários antes do plano Developer da Groq (decisão e custo do Marcelo).**
- **D-G11 Contratos da rota/cliente fixados pelos testes:** `createGroqModelPort({ apiKey, model?, fetch, now, deadlineAt, callTimeoutMs? })`; pedido com EXATAMENTE `model, messages, tools, tool_choice, reasoning_effort:"none", reasoning_format:"hidden", max_tokens:1500, temperature:0.2`; 413/429 ⇒ `RATE_LIMITED`; `handleChatPost(ctx, req)` com `ctx = { userId, getPlan, rateLimit, globalGuard, deps, makeModel(deadlineAt), clock:{iso(),ms()}, newLeaseId() }`; `buildAiPartnerChatDeps(env, prisma, { fetch? })` ⇒ `{ ok:true, deps, makeModel }` | `NOT_CONFIGURED`.

## 6. Emenda (21/10/2026) — Free mínimo e ordem da guarda global
- **D-G5 ordem revista:** sessão → configurado → Origin → limite por minuto → corpo → plano → pin/`NO_IMPORTS` → `withChatQuota` { reserva do usuário (+ pool no Free) → **guarda global da Groq** → `runChatTurn` }. A guarda vira parte do turno (resultado `BUSY` devolve a cota). Motivo: Free sem cota ou sem pool não pode consumir a guarda global nem travar pagantes.
- **Novo código HTTP:** `FREE_POOL_EXHAUSTED` ⇒ 403 `{upgrade:true, suggestedPlan:"TRADER"}`; `BUSY` ⇒ 429 com `Retry-After` (cota devolvida).
- Testes ajustados: H6, H9, H11 (Free = 3), H15 (nova ordem), H21 (pool esgotado).
